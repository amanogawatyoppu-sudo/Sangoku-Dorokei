# TRI//TRACE : TOKYO v8.2

**3勢力。9戦区。敵のANCHORを追え。**

東京・山手線内9戦区を舞台に、3勢力が戦う3D追跡ストラテジー。
敵勢力に隠されたANCHORを追跡・推理し、背後からTRACEしてLOCK POINTへ拘束する。
戦区・前線・高低差・救援・情報戦・一時停戦によって、試合展開は毎回変化する。

> 東京・山手線内は9つの戦区に分断された。
> SOL、LUNA、ASTER。3勢力は前線を奪い合いながら、敵部隊に隠されたANCHORを追う。
> 戦況を読み、痕跡を追跡し、敵の背後を取れ。ANCHORをLOCKし、東京の戦線を制圧せよ。

ブラウザだけで遊べます（インストール不要・スマホ対応）。CPU戦（初級〜超級）と、友達との対人戦に対応。

## 遊び方

1. **所属勢力と役職を選ぶ** — SOL / 太陽陣営（新宿）・LUNA / 月陣営（上野）・ASTER / 星陣営（高輪）
2. **痕跡を追う** — 敵勢力のANCHORは普通のメンバーに紛れていて、誰なのか分からない。
   護衛の付き方、移動経路、前線での動き、救援の集中、会議で出た証言からANCHOR候補を推理する
3. **背後を取ってTRACE** — TRACEは敵の背後から相手を拘束する基本アクション（正面からはできない）
4. **LOCK POINTへ拘束** — TRACEされた人は相手勢力のLOCK POINTに拘束され、仲間のBREAKERが解除するまで動けない
5. **NETWORK LOST** — ANCHORが時間内（80秒）に解放されなければリンクが切断され、その勢力は戦線離脱
6. **NETWORK SECURED** — 最後までネットワークを保った勢力の勝利。時間切れなら戦功ポイントで決まる

## 特徴

- **東京・山手線内の立体マップ** — 実在の駅と名所を緯度経度から配置。階段・屋上・歩道橋・首都高の高架・高台など高低差のある街
- **9戦区と前線** — 戦区の拠点に立ち続けると制圧。勢力圏が接する前線は試合中に動き続ける
- **3勢力AI** — 各勢力のCPU司令が戦況を読み、侵攻・防衛・ANCHOR捜索・解放作戦・終盤の得点判断を自分で決める。
  2勢力が争う隙を3つ目が突く「漁夫の利」も起きる
- **TRUCE（一時停戦）** — 強すぎる勢力に対抗して、残りの2勢力が短い停戦を結べる
- **管制塔** — 占領するとRELAYのレーダーが使え、終盤はANCHOR SCANで敵のANCHORを光の柱で照らし出せる
- **会議** — ハーフタイム会議と緊急会議。観測した情報を出し合い、ANCHOR候補と捜索先を決める
- **役職連携** — 6役職がそれぞれの役割で連携する。プレイヤーには分隊が付く（付いてこい・警戒・守れ）
- **CPU難易度** — 初級・標準・上級・超級（変わるのはCPUの判断だけ）
- **対人戦** — 部屋コードを共有するだけで、ブラウザ同士が直接つながる（最大9人・残りはCPU）
- **貢献度ランキング** — 試合後に全員の貢献度・順位・称号（TRACE MASTER、ANCHOR HUNTER、HIGH GROUND など）
- **夕暮れから夜へ** — 試合が進むと夜になり、街灯の下にいる人だけが遠くから見える

## 役職

| 役職 | 読み / 役割 | 概要 |
|---|---|---|
| ANCHOR | アンカー | 勢力の情報・指揮ネットワークの中枢。正体を隠して生き延びる。回避能力、正面からでもTRACEできる、1回だけDECOY（身代わり） |
| VANGUARD | 前衛 | 前線戦闘・護衛・戦区防衛。TRACEに3回耐える |
| SPOTTER | 観測手 | 高所から敵を観測し、遠距離から撃って3秒スタンさせる |
| RELAY | 中継手 | 管制塔の確保が最速。レーダーで戦況を共有する |
| BREAKER | 解除士 | LOCK POINTの拘束を解除して味方（ANCHORも）を解放する |
| RUNNER | 遊撃手 | 追跡・高速救援・前線移動。階段や坂でも速い。特殊「疾走」 |

## 操作

PC: ↑↓ 前進・後退 / ←→ 旋回 / Shift 加速 / Space TRACE（敵の背後から） / Z 特殊（BREAKER・ANCHORはLOCK POINTの仲間のそばで解除） /
Q 180°振り向き / B ANCHOR SCAN（管制塔） / 1〜4 合図（ANCHOR・助けて・集合・敵多数） / F DECOY（ANCHORのみ） /
分隊: X 付いてこい・C 周りを警戒しろ・V ここを守れ / ドラッグで上下の傾き・ホイールで距離

スマホ: 左下ジョイスティック（上下で前後、左右で旋回）、右下の TRACE・特殊・ダッシュ・振向、画面の上下スワイプで傾き。

カメラは常にキャラクターの背後にあり、背中側は見えません（背後を取るゲームなので）。確認したいときは Q で振り向きます。

## 友達と遊ぶ

1. ホストが「PLAY」→ ゲーム設定の「5 CPU戦 / 対人戦」で **対人戦** →「部屋を作る」。部屋コード（5 文字）が出る
2. 友達は同じ URL（GitHub Pages など）をブラウザで開き、対人戦 → 部屋コードを入れて「部屋に参加する」
3. 全員そろったらホストが開始。同じ勢力なら味方、別の勢力なら敵

GitHub Pages や保存した HTML ではブラウザ同士が WebRTC で直接つながります（相手を見つけるときだけ公開の Nostr リレーを使用）。
会社・学校のネットワークなど、直接接続が許されない環境同士ではつながらないことがあります。

## ルールの詳細

- **TRACE**: 真後ろなら確実、斜め後ろは 15%、横は 50% の確率で失敗。足元の輪が緑ならTRACEできる相手
- **LOCK POINT**: ANCHORは 80 秒、ほかは 50 秒で時間切れ（戦線離脱）。ANCHORが拘束されたLOCK POINTは 45 秒間全勢力に知られる
- **解放**: BREAKER・ANCHOR・「最後の一人」ができる。BREAKER以外は 1.5 倍時間がかかる
- **戦功ポイント**（時間切れ）: TRACE×3・解放×3・ANCHORへの攻撃×2・生き残り×2・管制塔 15 秒ごとに 1・自勢力のANCHORが拘束中なら −10
- **ANCHOR SCAN**: 残り 1:40 から、管制塔を持つ勢力が敵のANCHORを 12 秒間照らせる（再使用 40 秒）
- **TRUCE**: 45 秒の一時停戦（1 試合 2 回）。停戦中の2勢力は互いにTRACEしない
- タイトルの「用語・戦場マップ」で、すべての用語と9戦区の詳細をいつでも確認できる

## マップ

舞台は東京・山手線の内側。駅と名所は実際の緯度経度から配置しています。

- 人・建物・道路は実物大の比率（キャラクター ≈ 1.7 m、1 m ≈ 26 単位）。街と街の距離だけ縮めています
- 勢力の拠点: SOL = 新宿三丁目、LUNA = 上野広小路、ASTER = 高輪。管制塔 = 日比谷公園の電波塔
- 名所: 皇居と堀、東京駅丸の内駅舎、国会議事堂、東京タワー、愛宕山の石段、上野の山、神田川と聖橋、東京ドーム、国立競技場、首都高の高架、歩道橋など
- 街並み・建物・キャラクター・UI・効果音・BGMはすべてコードで生成しています

## 構成

```
src/
  main.ts               組み立て（状態・描画・UI・入力をつなぐ）
  config/               勢力・役職・マップ・バランス定数
    terminology.ts      プレイヤーに見せる用語の一元管理（ANCHOR・TRACE・LOCK POINT・勢力名など）
  core/                 clock（固定ステップ）/ loop / events（EventBus）/ rng
  sim/                  ゲーム状態とルール（DOM・Three.js・音声に触れない）
  ai/                   経路網・知覚・行動・勢力の司令・作戦
  meeting/              会議
  net/                  対人戦（状態の圧縮・同期・部屋）
  input/                キーボード + タッチ
  render/               3D 描画（街・キャラクター・カメラ・生成テクスチャ）
  ui/                   HUD・ログ・ミニマップ・各画面・イベント→文言
  audio/                効果音・BGM（生成）
tests/                  Vitest
legacy/                 最初期の単一HTML版（比較用）
```

### 設計ルール

- ゲーム時間は `state.time` だけ。60Hz の固定ステップ（`stepSimulation`）でのみ進む
- sim は出来事を `GameEvent` として積むだけ。UI・音声がそれを受けてログ・演出・効果音を出す（`ui/messages.ts`, `audio/sfx.ts`）
- プレイヤーに見える用語は `src/config/terminology.ts` から使う。内部の識別子（勢力 `sun / moon / star`、役職 `king / soldier / …`、
  イベント `KING_CAPTURED` など）は互換性のため旧来の名前のまま
- `tests/architecture.test.ts` が sim/ai/meeting/core/config から three・DOM・音声・実時間タイマーを使っていないことを検査する
- `tests/brand.test.ts` が画面に出る文字列に旧用語が残っていないことを検査する
