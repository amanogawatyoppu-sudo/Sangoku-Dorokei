# GLB Character Integration Test（v9.1 ベース・プレイヤー1体のみ）

SOL の試作 GLB（`TRI_TRACE_SOL_animated_v02.glb`）を、プレイヤー1体だけに試験導入した。**ここで止めています。** CPU・オンラインの他プレイヤーは従来モデルのままです。

## 使い方・切り戻し
- フラグ: `src/render/glbCharacter.ts` の `EXPERIMENTAL_GLB_CHARACTER`（既定 `false`）
- 確認用: アドレスに `?glb=1` で ON、`?glb=0` で必ず OFF
- 従来の生成処理はそのまま残している。GLB が読めなかった場合も従来モデルが表示される

## 事前調査（v9.1 HEAD 074c235）
- テスト 39ファイル 301件 合格、ビルド成功（1131 kB）
- 描画: `EntityView` が全員分の手続き生成モデル（`buildHuman`、18本の骨のスキンメッシュ）を作り、毎フレーム位置・向き（+Z が前）・勢力色（変装を含む `effNation`）・役職装備・表情・骨のポーズを更新する
- カメラ: `CameraController`（距離160・傾き0.42、壁で縮むときはプレイヤーを半透明に、建物の陰では x-ray のシルエット）
- GLB の中身: Y-up・足元原点・高さ約2.06・正面+Z。スキンではなく、12個のノードを回転させる剛体アニメーション。71メッシュ、11,600三角形、頂点カラーのみ（マテリアル・法線なし）。勢力色は1色（RGB 248,105,39）と端末画面の淡色だけ

## 実装
- プレイヤーの従来モデルは「見えないリグ」として残す。位置・当たり判定・TRACE判定・速度・ルール・エフェクト・オンライン同期は従来と同じ値で動き、見た目だけを GLB で描く
- 読み込み: `GLTFLoader`。GLB はページ内に同梱（単一ファイルのまま。ページは 1131 → 1535 kB）
- 描画の最適化: 71メッシュを、動く12パーツをそれぞれ「骨」とした**1つのスキンメッシュ**にまとめた（剛体なので見た目は同じ）。本体1回＋x-ray 1回＋影1回で描ける
- アニメーション: `AnimationMixer` と6クリップ。切り替えは 0.2 秒（TRACE は 0.1 秒）のクロスフェード
  - 既存の移動状態から選ぶ: 速度 20 未満は Idle、〜150 は Walk、〜300 は Run、それ以上は Sprint。その場や歩く速さで向きを大きく変えると Turn、TRACE 成功時は Trace（1回再生）。境目でちらつかないよう ±15 の幅を持たせた
  - 歩き・走り・ダッシュは、既存の歩幅に合わせて再生速度を変える（足が滑りにくい）。クリップ間で歩行の位相を引き継ぐ
  - 旋回時の傾きは従来と同じ値を GLB にも適用。アニメーションはその場で再生され、移動はシミュレーションのまま
- 向き: GLB の正面（+Z）はゲームの前方と一致していた。回転の補正は不要（入力・背後判定は変更なし）
- 勢力色: 橙のパーツを、自分の勢力（変装中はその色）に塗り替える。LUNA・STAR で配属されても正しい色になる
  - 昼の光で橙が黄色（STAR）に見えたため、少し暗くし、夜も見えるよう弱く発光させた
- 半透明（カメラが詰まったとき）と、建物の陰の x-ray シルエットも GLB に対応

## 確認結果
- **6クリップすべてが実ゲーム内で再生されることを確認**（Idle・Walk・Run・Sprint・Turn・Trace）
- 足の接地: 全クリップの各時点で足が地面に届き、めり込まない（テスト）。実画面でも、走行中に身体は浮いていない
- カメラ: 通常距離で身体にめり込まない。壁際でカメラが詰まると従来どおり半透明になる
- 正面・背面の向きは正しい
- 回帰（本番ビルド、GLB オン／オフ）
  - 背後からの TRACE → LOCK POINT、階段（+59）、会議は両方とも同じ結果
  - テストは 40ファイル 307件 合格（新規6件）

## 性能（本番ビルド、HIGH、1366×768、同じ10地点）

|---|---|---|
| 描画呼び出し（平均） | 236.0 | 231.8（差は CPU 人物の位置の違いの範囲） |
| 三角形（平均） | 142,900 | 159,037（+約1.6万。本体・x-ray・影の3回 × 11,600 から従来分を引いた量） |
| テクスチャ | 82.6 MB | 82.6 MB |
| 頂点・インデックス | 11.6 MB | 13.5 MB（+1.9 MB） |
| fps（CPU描画・参考） | 2.01 | 1.98 |

- メッシュ分割のまま（71 → 12パーツ別）だと、描画呼び出しは +20 だった。1つのスキンメッシュにして差がなくなった
- **実GPUは利用できない**（この環境は SwiftShader の CPU 描画）。フレーム時間は実機で `?debug&glb=1` を開き、`__sangoku.frameStats()` で測れる
- 全NPCに広げた場合の目安: 1体あたり +約1.2万三角形（影と x-ray を除く）、30人で +約35万三角形。今回は広げていない

## 影響を与えていないもの
- CPU戦のランダム配属、敵の役職隠し、ANCHOR の変装、オンライン同期: GLB はローカルのプレイヤーの見た目だけ。判定・同期データは触っていない
- 他のキャラクターはすべて従来モデル

## 問題・判断が必要な点
- **通常カメラ（後ろから見下ろす）では、ほぼ紺一色のシルエットに見える**
  - 背中の勢力色が小さな縦線だけで、従来モデル（背中ユニットが大きく光る）より勢力が分かりにくい
  - 夜はさらに暗い。顔・髪の魅力は正面からでないと見えない
  - 背中・肩の勢力色の面積を増やすのはモデル側の修正が望ましい
- 役職装備がない（自分の役職装備は表示されない）。表情・TRACE 端末の発光演出もない（GLB に仕組みがない）
- 拘束中・解除中・スタン中の専用ポーズがなく、Idle で立ったまま
- Turn は「その場」か「歩く速さ」での向き変えのみ。走行中の急旋回は Sprint のまま、傾きで表現
- 走りは剛体アニメーションのため関節が硬く、横から見ると脚の動きがやや機械的
- ページが約400 kB 増える（GLB と GLTFLoader の同梱。フラグがオフでも読み込まれる）
