## 1. 検証結果（何が分かったか）

### 1-1 敵の役職が見た目で確定する（v9.0 の問題・確認済み）
- v9.0 は役職装備を常に表示していた。敵の SPOTTER は常にマーカーを持って低く構え、VANGUARD は肩アーマー、RELAY はアンテナを付けていた（`1-roles-crop.jpg` 左）
- ANCHOR は VANGUARD か RUNNER の装備を借りていた。そのため、見た目が「VANGUARD 風・RUNNER 風」の人数と編成の人数を比べると、初見で候補が絞れた
  - 6人編成（各役職1人）: ANCHOR が VANGUARD の見た目なら、VANGUARD に見える2人のどちらか（50%）
  - 10人・15人編成でも、候補は「その見た目の人数」まで減った
- SPOTTER だけは待機ポーズも違った（構えたまま）

### 1-2 AI の不正な情報利用（問題なし・確認済み）
- `src/ai` の役職参照はすべて自勢力のもの
- 敵のANCHORは観測・確信度・会議で追う。拘束中の敵ANCHORの判定（`faction.ts`）は、ゲーム内で公開済みの情報（ANCHOR LOCKED）だけを使う
- AI は描画を一切参照しない（`architecture.test.ts` で検査）

### 1-3 見た目以外の手がかり（未修正・ゲームバランスに関わるため報告のみ）
- CPU の ANCHOR は逃走時以外 25% 遅く歩く（`controller.ts` の速度係数 0.75）。行動を見れば推理の手がかりになる
- 正面から確実に TRACE できる（スーパーハンド）、DECOY を使える、のは ANCHOR の能力そのもの
- ANCHOR の回避強化はログに「○○のANCHORが回避を強化」と出る（誰かは出ない）

### 1-4 ビジュアル
- **白飛び（昼）**: 原因は戦略拠点の光の柱と床の輪（加算合成）が、明るい舗装の上で飽和すること。白飛び画素（3D画面の最大値 ≥250）は v9.0 で渋谷 5.3%・秋葉原 5.8%
- **夜**: 全体の青かぶりが強く（B−R 平均差 +22〜+51）、LUNA の青い発光ラインが街に埋もれ気味
- **キャラの向き**: 背面・側面・正面とも正しい向き（`2-character-close.jpg`）
- **勢力識別**: 昼夜とも背中ユニットと肩の色で識別できる
- **階段入口**: 上野の丘の石段は昼は読める。夜は暗い踏面と暗い斜面で輪郭が弱い（v9.1 で青かぶりが減り少し改善、未解決）。東京タワー下の石段は、昼に戦略拠点の光で入口が見えにくい（v9.1 で光を弱め少し改善）
- **路上の戦区らしさ**: カメラが見下ろす角度のため、路上からは高層のネオンや屋上の光がほとんど見えない（v9.0 からの既知の弱点、未修正）

## 2. 修正内容（v9.1）
1. **全役職が共通の制服**。ベストと背中ユニットも全員同じ形にした。役職装備は別レイヤーにし、次のルールで表示する
   - 自勢力には常に表示（名札の役職表示もそのまま）
   - 敵には、その役職だけの能力を使ったときだけ短時間表示
     - VANGUARD: TRACE に耐えた・回復した → 6秒
     - RELAY: レーダー → 6秒
     - RUNNER: 疾走中 ＋3秒
     - SPOTTER: 狙っている・撃った ＋2秒
   - **ANCHOR と BREAKER は敵に一切表示しない**。解除は ANCHOR と「最後の一人」もできるので、BREAKER の工具だけ見せると、工具なしで解除する人が ANCHOR だと分かってしまうため
   - 敵の SPOTTER は使っていないとき、マーカーも構えのポーズもない
   - 実装は `src/render/gearReveal.ts`（表示ルール）と `humanModel.ts`（装備レイヤー）
   - 制服だけの形状は、全身の形状とバッファを共有し、描く範囲だけを短くしている（頂点メモリの追加なし）
2. **昼の戦略拠点の光を弱め、夜は従来どおりにした**。白飛び画素は渋谷 5.3% → 1.4%、秋葉原 5.8% → 3.3%
3. **夜の青かぶりを抑えた**。月明かりと空からの環境光を中立寄りにした。B−R 平均差は渋谷 22 → 11、上野 25 → 15、秋葉原 51 → 38 で、明るさは同等かやや明るい
4. 検証用の `?debug` フックを追加した（通常プレイには影響なし）
   - 写真用: 一時停止・カメラの回り込み・寄り・人物配置・疾走フラグ・配属固定（`&deal=`）
   - 計測用: `frameStats()`（実機のフレーム時間）、`memory()`（テクスチャ・頂点の使用量）
   - 遅い端末向けの追いつき処理が、一時停止を無視していた点も直した（デバッグ時のみ関係）

### 消去法の検証（`tests/roleVisibility.test.ts`）

| 編成 | 初見でANCHORの候補 | 見える行動をすべて見た後の候補 |
|---|---|---|
| 6人 | 6人（全員同じ制服） | 2人（ANCHOR＋BREAKER 1人） |
| 10人 | 10人 | 3人（ANCHOR＋BREAKER 2人） |
| 15人 | 15人 | 3人（ANCHOR＋BREAKER 2人） |

- 装備の表示は、もともと目に見える行動に結びつけてある。つまり、見た目が行動以上の情報を与えることはない
- 「見える行動をすべて見た後」は、全員の能力使用を見て覚えていた場合の最悪ケース

## 3. 性能（同じ9地点、HIGH、1366×768）
SwiftShader（CPU描画）のため、fps は相対値のみ。実機の GPU 性能はこの環境では測れない。

| | v8.4 | v9.0 | v9.1 |
|---|---|---|---|
| 描画呼び出し（平均） | 229 | 231 | 232 |
| 三角形（平均） | 119,248 | 139,260 | 139,662 |
| テクスチャ（`memory()`、推定） | 104枚 / 83.3 MB | 101枚 / 82.6 MB | 101枚 / 82.6 MB |
| 頂点・インデックス（シーンに付いているもの） | 7.0 MB | 11.6 MB | 11.5 MB |
| fps（CPU描画、参考） | 2.24 | 2.17 | 2.17 |

- 制服だけの形状はバッファ共有にした。共有しない場合の 30人分 +7.7 MB は発生しない
- 実機での測り方: `?debug` で開いて10秒ほどプレイし、コンソールで `__sangoku.frameStats()` を実行する（p50/p95/p99 と GPU 名が出る）

## 4. 回帰確認
- 既存テスト＋新規: 39ファイル 301件すべて合格。カメラ遮蔽、経路網、階段、TRACE、LOCK POINT、会議、オンライン同期（スナップショット・P2P部屋）を含む
- 実ゲーム（Playwright、v9.0 と v9.1 で同じ手順）
  - 背後からの TRACE で LOCK POINT へ: 両版とも成功（LOCK POINT から 6〜8 単位）
  - 会議: 両版とも開く
  - 階段: 両版で同じ上昇量（シミュレーション 0.6 秒で +59）
- AI のみの対戦: 6・10・15人 × 各6シード。全試合が最後まで進み、目的のない状態は 0.5〜0.8%。シミュレーションのコードは v8.4 から未変更
- オンライン: スナップショットは HP・疾走・照準・能力クールダウンを既に送っているので、装備表示は追加同期なしでクライアントでも同じに動く。実際の2台接続はこの環境では試していない（外部リレーに接続できない）

## 5. 未検証・未解決
- 実GPUでのフレーム時間（この環境に GPU がない）
- 敵の装備が「表示される瞬間」の実ゲーム画像。CPU描画ではシミュレーションが実時間の約7%でしか進まず、AIが狙う・疾走する場面を撮れなかった。表示ルールは単体テストで確認した
- 夜の階段入口の視認性、路上での戦区らしさの弱さ（上記 1-4）
- CPU の ANCHOR の歩く速さという行動上の手がかり（上記 1-3）
